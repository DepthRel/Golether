# Запуск Android-эмулятора

Как подготовить компьютер с Windows к запуску Android-клиента Golether в эмуляторе. Android Studio не нужна. Скрипты
сами приводят устройство в рабочее состояние: клавиатура, кнопки навигации и ускорение графики работают сразу после
установки.

## Быстрый старт

Нужны Windows 10 или 11 (64-разрядная), включённая виртуализация в настройках BIOS/UEFI и около 10 ГБ свободного места.
Запустите скрипты из `Scripts/Android` в таком порядке, достаточно двойного щелчка:

| Шаг | Скрипт | Права администратора | Что делает |
|---|---|---|---|
| 1 | `enable-windows-features.bat` | да, запросит сам | Включает платформу низкоуровневой оболочки Windows. Затем **перезагрузите Windows** |
| 2 | `install-android-tools.bat` | да, запросит сам | Ставит .NET Android workload, JDK, Android SDK и эмулятор: около 6 ГБ, загрузки проверяются по SHA-256 |
| 3 | `create-emulator.bat` | нет | Создаёт устройство `Golether-API36`, запускает его и кладёт ярлык на рабочий стол |

После этого эмулятор запускается ярлыком **Android Emulator (Golether-API36)** или скриптом `start-emulator.bat`. Он каждый раз загружается заново: снимок для быстрого старта занял бы 4 ГБ и перезаписывался бы при каждом выходе.
После неудачного выхода эмулятор спрашивает, отправить ли отчёт о сбое, и ждёт ответа с выключенным устройством;
закройте это окно.

Из командной строки устройство корректно выключается командой `adb shell reboot -p`; `adb emu kill` считается аварийным выходом. У устройства есть только задняя камера: чтобы проверить переключение между двумя камерами, запустите эмулятор один раз с `-camera-front emulated`.

Шаги 2 и 3 можно повторять: установленное остаётся, у существующего устройства сохраняются данные.

## Что и куда ставится

| Что | Куда |
|---|---|
| .NET Android workload | Папка .NET, `C:\Program Files\dotnet\packs`: workload всегда ставится туда |
| Microsoft OpenJDK 21 | `C:\Program Files\AndroidTools\jdk-21` |
| Android SDK, эмулятор, образ системы | `C:\Program Files\AndroidTools\sdk` |
| Виртуальные устройства | `%USERPROFILE%\.android\avd`: эмулятор пишет туда во время работы, поэтому в Program Files они лежать не могут |

`JAVA_HOME` и `ANDROID_HOME` задаются для всех пользователей. Чтобы их увидеть, перезапустите терминалы и Visual Studio.

Папки меняются двумя переменными: `ANDROID_TOOLS_ROOT` для инструментов и `ANDROID_AVD_HOME` для устройств. С
`ANDROID_TOOLS_ROOT` права администратора не нужны (если workload уже стоит), но `JAVA_HOME` и `ANDROID_HOME` тогда
задаются вручную.

## Настройки устройства

`avdmanager` создаёт устройство, с которым неудобно работать, поэтому `create-emulator.bat` его меняет:

| Настройка | По умолчанию | Ставит скрипт | Зачем |
|---|---|---|---|
| `hw.keyboard` | `no` | `yes` | Иначе клавиатура компьютера ничего не вводит |
| `hw.gpu.enabled` | `no` | `yes` | Иначе изображение рисует процессор: система тормозит, а видео остаётся без OpenGL ES |
| `hw.gpu.mode` | `auto` | `auto` | Видеокарта, когда возможно, а на компьютере без неё — отрисовка процессором |
| `hw.ramSize` | `2G` | `4G` | 2 ГБ мало для Android 16 с Google APIs |
| Навигация | жесты | три кнопки | При жестах кнопок на экране нет, а жесты неудобно делать мышью |

Первые строки — это `config.ini` устройства. Навигация задаётся в запущенной системе и там сохраняется:

```powershell
adb shell cmd overlay enable-exclusive --category com.android.internal.systemui.navbar.threebutton
```

## Работа с эмулятором

- Вместе с эмулятором запускается свёрнутое окно консоли. Если его закрыть, эмулятор закроется.
- Компьютер доступен из эмулятора по адресу `10.0.2.2`.
- Пока включена физическая клавиатура, экранная не появляется: это нормально.
- Эмулятор не покажет настоящее аппаратное декодирование видео, нагрев и скорость телефона: для этого нужен настоящий
  телефон, подключённый по USB, с включённой отладкой по USB.
- `sdkmanager` и `adb` не добавлены в `PATH`. Они лежат в `C:\Program Files\AndroidTools\sdk`, в папках
  `cmdline-tools\latest\bin` и `platform-tools`. `sdkmanager` пишет в Program Files, поэтому ему нужен терминал от
  имени администратора.

## Сборка и запуск клиента

Android-проекты не входят в сборку `Golether.slnx`: она должна работать без Android workload. Они собираются отдельно,
и им нужны нативные компоненты в `Native/android-*` (см. `Native/README.md`):

```powershell
dotnet build Sources/Apps/Golether.Mobile.Android -t:Install
```

С `-p:GoletherDeviceChecks=true` в пакет добавляются проверки того, что можно доказать только на устройстве: данные,
ключи, TLS, libmpv, GStreamer. Они запускаются параметром Activity и отвечают в logcat с тегом `GOLETHER-CHECK`:

```powershell
adb shell am start -n depthrel.golether/depthrel.golether.MainActivity --ez golether.checks true --ez golether.conference true
adb logcat -s GOLETHER-CHECK
```

## Проблемы

| Что видно | Что это значит |
|---|---|
| `sdkmanager` не распознан как команда | Его нет в `PATH`: укажите полный путь или запустите `install-android-tools.bat` |
| Отказ в доступе при установке через `sdkmanager` | Терминал запущен не от имени администратора |
| `WARNING: The SDK Manager CLI tool (sdkmanager) is deprecated` | Предупреждение, а не ошибка |
| `Error: Could not load devices from ...\devices.xml` от `avdmanager` | Безвредно: в образе нет такого файла, устройство создаётся |
| Клавиатура ничего не вводит или система тормозит | Устройство создано вручную: запустите `create-emulator.bat`, он сохранит данные и исправит настройки |
| Эмулятор очень медленный, шаг 1 пропущен | Запустите `enable-windows-features.bat` и перезагрузите Windows. Проверка: `emulator -accel-check` |
| `enable-windows-features.bat` завершается ошибкой | Виртуализация выключена в настройках BIOS/UEFI |
